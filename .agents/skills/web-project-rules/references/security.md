# 安全规范

## 原则

- 所有来自用户、URL、存储、API、第三方组件和富文本内容的数据默认不可信。
- 前端校验用于用户体验，不能替代服务端授权、鉴权和数据校验。
- 最小权限、最少数据、最短保留时间优先。
- 安全失败必须进入可控状态，不能通过关闭检查继续执行。

## 内容渲染与 XSS

- 默认使用 React 文本插值，让框架进行转义。
- 原则上禁止 `dangerouslySetInnerHTML`。
- 必须渲染 HTML 时，只能使用经过明确允许列表净化的内容，并把净化集中在可信边界。
- Markdown、富文本、模型输出和第三方内容均视为不可信；链接、图片、代码块和嵌入内容必须经过协议和属性限制。
- 禁止把不可信字符串拼入脚本、样式、选择器或事件处理属性。
- 不使用 `eval`、`new Function` 或字符串计时器执行动态代码。

## URL 与导航

- 外部 URL 必须解析并限制允许协议，拒绝 `javascript:` 等可执行协议。
- 用户提供的路径不能直接用于开放重定向。
- 新窗口链接使用必要的隔离属性，避免目标页面控制当前页面。
- 下载、图片和嵌入资源应限制来源和类型。
- 敏感信息不得放入 URL、浏览器历史、Referer 或可分享状态。

## 认证与授权

- UI 隐藏按钮不等于授权；所有受保护操作必须由服务端验证权限。
- 认证状态必须有明确的初始化、过期、刷新、注销和多标签页同步行为。
- 不在可被任意脚本读取的长期存储中保存高价值凭据，除非整体安全设计明确接受风险。
- Cookie 鉴权必须配合适当的 SameSite、Secure、HttpOnly 和 CSRF 策略。
- 注销必须清理客户端敏感状态和缓存，不能仅跳转页面。
- 不向不同用户复用可能包含私密数据的持久化缓存。

## 输入与数据

- 所有表单和 URL 输入必须限制类型、长度、格式和允许值。
- 文件上传必须检查数量、大小、类型和扩展名；客户端检查不能替代服务端内容验证。
- 不使用前端可修改的数据决定价格、权限、身份或其他安全关键事实。
- 从存储和 API 读取的数据在进入领域模型前进行运行时校验。
- 错误信息不能泄漏内部路径、堆栈、数据库结构或安全策略细节。

## 密钥与配置

- 浏览器构建中的环境变量和代码都视为公开信息。
- 禁止在前端保存服务器密钥、私钥、管理令牌或任何依赖保密性的凭据。
- `.env` 实际值、生产配置和凭据文件不得提交。
- 示例环境文件只能包含变量名和无敏感性的占位值。
- 配置缺失时必须明确失败或使用安全默认值，不能回退到生产外部地址。

## 请求安全

- 请求只发送操作所需的最少字段和凭据。
- 写操作必须考虑重复提交、重放和并发覆盖。
- 自动重试不能作用于非幂等写操作，除非协议提供幂等保护。
- 跨域、凭据和重定向策略必须明确，不使用不受控通配。
- 日志和监控数据必须脱敏，不记录密码、令牌、Cookie、完整请求头和用户私密正文。

## 依赖与供应链

- 依赖只从项目批准的包管理来源安装。
- 新依赖必须检查维护状态、许可证、安装脚本、权限和传递依赖风险。
- 不执行来源不明的复制脚本和安装命令。
- 锁文件必须提交并在依赖变更时接受评审。
- 安全更新应单独评估破坏性变化，不能因版本号更新直接跳过测试。

## 浏览器和部署防护

- 应由部署层配置合适的内容安全策略、点击劫持保护、MIME 嗅探保护和 Referrer 策略。
- 前端不得依赖关闭这些防护才能运行。
- 使用摄像头、麦克风、剪贴板、通知和文件系统等能力时，只在用户明确操作后申请最小权限。
- 权限拒绝必须可恢复，不能阻止应用其他功能启动。

## 安全评审

涉及认证、权限、富文本、文件、外部 URL、持久化和第三方接口的变更必须在评审说明中标记安全影响，并覆盖失败路径。无法确认安全边界时不得依靠前端猜测继续实现。

## 项目案例

以下案例覆盖本文件全部规则章节。案例说明前端责任，但任何前端检查都不替代服务端授权和验证。

### 案例：不可信输入失败时进入安全状态

**覆盖**：所有输入不可信、服务端仍负责安全、最小权限/数据/保留、安全失败不可绕过。

- ❌ API 返回未知角色时默认提升为管理员，或关闭校验继续渲染受保护操作。
- ✅ 未知角色解析失败并进入无权限或可恢复错误状态；服务端对每个写操作重新鉴权。
- ✅ 只请求和保留当前界面所需字段，用户退出后清理私密状态。

### 案例：React 文本与受控富文本

**覆盖**：默认转义、限制 `dangerouslySetInnerHTML`、集中净化、Markdown/模型输出限制、禁止字符串注入与动态执行。

```tsx
// ✅ 普通用户内容交给 React 转义
<p>{userProfile.biography}</p>

// ❌ 未净化 HTML
<article dangerouslySetInnerHTML={{ __html: modelOutput }} />
```

确需 HTML 时，在单一可信边界使用允许列表净化，并限制链接协议、图片来源、属性和嵌入。不能把输入拼进 `<style>`、选择器、事件属性，也不能使用 `eval`、`new Function` 或字符串计时器执行它。

### 案例：外部链接和导航

**覆盖**：协议允许列表、开放重定向、新窗口隔离、资源来源/类型、禁止敏感 URL。

```ts
function parseExternalUrl(value: string): URL | null {
  try {
    const url = new URL(value);
    return url.protocol === "https:" ? url : null;
  } catch {
    return null;
  }
}
```

- ❌ `window.location.href = searchParams.get("next")`，可能开放重定向。
- ✅ 站内返回路径只接受允许的相对路由；外链新窗口同时使用必要隔离属性。
- ❌ 把 token、身份证号或私密正文放进 Query、历史或可分享 URL。
- ✅ 下载和嵌入限制批准来源、协议与文件类型。

### 案例：UI 权限不是授权

**覆盖**：服务端授权、认证生命周期、凭据存储、Cookie 属性/CSRF、注销清理、用户缓存隔离。

- ❌ 只隐藏“删除账户”按钮就认为普通用户无法调用接口。
- ✅ UI 根据权限改善体验，服务端仍验证当前会话和操作权限。
- ✅ 认证状态明确区分 initializing、authenticated、expired、refreshing、anonymous，并处理多标签注销。
- ✅ Cookie 方案由服务端设置合适属性并配套 CSRF；不随意把高价值凭据放长期脚本可读存储。
- ✅ 注销清除会话、私密查询缓存和用户专属状态，再导航；不同用户绝不共享持久化私密缓存。

### 案例：输入、文件和领域事实

**覆盖**：类型/长度/格式/允许值、文件边界、服务端内容校验、前端数据不可决定安全事实、运行时校验、错误脱敏。

- 用户名：客户端限制长度和允许字符，服务端再次验证。
- 文件：客户端检查数量、大小、声明 MIME 和扩展名；服务端检查真实内容、病毒与权限。
- ❌ 根据隐藏 input 中的 `price` 或 `isAdmin` 决定收费和权限。
- ✅ 从 URL、存储、API 进入领域模型前运行时校验；错误只展示稳定错误码对应文案，不泄漏路径、堆栈、表结构或安全策略。

### 案例：前端环境变量不是秘密

**覆盖**：浏览器公开性、禁止密钥、环境文件、示例占位、缺失配置安全失败。

```text
❌ VITE_ADMIN_PRIVATE_KEY=real-secret
❌ 提交 .env.production
✅ VITE_PUBLIC_API_BASE_URL=PUBLIC_API_ORIGIN
✅ .env.example 只写变量名和无敏感占位值
```

所有进入浏览器 bundle 的内容都能被用户读取。关键配置缺失时明确停止初始化或使用本地安全默认，不能偷偷回退到生产外部地址。

### 案例：请求最小化和写操作保护

**覆盖**：最少字段/凭据、重复提交/重放/并发、幂等重试、跨域策略、日志脱敏。

- 更新显示名只发送 `displayName`，不回传完整用户对象和无关权限字段。
- 提交按钮在 pending 时禁用；重要写操作使用版本检查或幂等键防止并发覆盖和重放。
- 非幂等请求没有协议保护时不自动重试。
- 跨域源与 credentials 明确列出，不使用不受控通配。
- 日志记录错误类别和 request ID，不记录 Cookie、密码、令牌、完整 headers 或用户私密正文。

### 案例：依赖与安装命令评审

**覆盖**：批准来源、维护/许可证/脚本/权限/传递风险、未知脚本、锁文件、安全升级测试。

- ❌ 从陌生评论复制 `curl ... | sh` 或安装来源不明的包。
- ✅ 使用仓库既定包管理来源，评估维护状态、许可证、install scripts、浏览器权限和传递依赖，再提交锁文件差异。
- ✅ 安全升级独立检查破坏性变化并运行完整验证；不能因为版本标记为 security fix 就跳过测试。

### 案例：部署防护和浏览器权限

**覆盖**：CSP/点击劫持/MIME/Referrer、防护兼容、用户操作后最小权限、拒绝可恢复。

- 部署层配置 CSP、frame 限制、`nosniff` 和合适 Referrer Policy；前端不通过内联任意脚本要求关闭 CSP。
- 只有用户点击“启用麦克风”后才申请麦克风权限，不在首页加载时同时请求摄像头、通知和剪贴板。
- 权限拒绝后显示可恢复说明，聊天的其他文本功能仍能使用。

### 案例：安全变更的评审说明

**覆盖**：认证、权限、富文本、文件、URL、持久化、第三方接口的显式安全评审与失败路径。

```text
安全影响：新增外部链接预览。
信任边界：URL 与预览元数据均不可信。
限制：仅 HTTPS；拒绝凭据型 URL；图片域名允许列表；不渲染原始 HTML。
失败路径：解析或加载失败显示普通链接，不执行重定向。
测试：javascript 协议、超长 URL、恶意 HTML、图片来源拒绝。
```

安全边界无法确认时停止实现并获取服务端或安全设计结论，不能靠前端猜测继续。

# 国际化规范

## 适用范围

适用于 `web/src` 中所有用户可见内容，包括页面、共享组件、上游组件的实际使用、错误提示、Toast、Tooltip、表单、图片替代文本、标题和 ARIA 文案。

## 基本要求

- 所有用户可见文案必须来自国际化资源。
- 禁止在 TS、TSX、JS、JSX 和业务 CSS 中硬编码面向用户的固定文字。
- 开发日志、内部错误码、测试说明和不会展示给用户的开发注释不属于翻译内容。
- 品牌名、协议标识、用户生成内容和后端业务数据不作为固定界面文案翻译；其周围的标签、说明和状态文案仍必须国际化。
- 翻译资源是文案的单一事实来源，组件不得维护第二套默认文案。
- 新增功能必须在同一变更中补齐所有受支持语言资源。

## 项目国际化边界

- `src/i18n` 是国际化基础设施的唯一入口。
- 翻译资源统一存放在 `src/i18n/resources/<locale>/<namespace>.json`。
- 支持语言、默认语言和语言偏好由 `i18n/locale.ts` 统一定义。
- 初始化、资源注册和 namespace 聚合由 `i18n/config.ts` 管理。
- 偏好读写、旧键迁移和存储事件校验由 `i18n/preference.ts` 统一负责。
- React 组件使用 `useTranslation(namespace)`；非 React 模块确有需要时才使用项目导出的 `i18n.t()`。
- 语言读取和切换统一通过 `useLocale()`；自定义 Hook 文件保留小驼峰 `useLocale.ts`，可复用语言按钮使用 `button-language.tsx` 并导出 `ButtonLanguage`。

## Locale

- Locale 标识必须使用规范的 BCP 47 格式，例如 `zh-CN`、`en-US`。
- 支持语言列表、默认语言和回退语言集中配置。
- 禁止在组件中自行判断浏览器语言或维护语言别名。
- 语言匹配必须处理区域回退，例如不能假设所有浏览器只返回两位语言码。
- 不支持的 Locale 必须回退到项目默认语言，不能导致应用初始化失败。

## 资源组织

- 翻译资源按稳定功能命名空间组织，例如 `common`、`auth`、`validation`。
- Key 使用小驼峰并表达语义，例如 `auth.login.submit`，不使用原始文案作为 Key。
- 通用文案只有在语义和翻译确实一致时才放入 `common`。
- 禁止为避免重复把上下文不同的文字强行共用同一个 Key。
- 删除功能时同步删除不再使用的资源；重命名 Key 时同时更新全部语言。
- 新增语言或 namespace 时同步更新资源注册和 `i18next.d.ts` 类型来源。

## 文案组合

- 禁止通过字符串拼接组装句子，不同语言的语序不能由代码假定。
- 变量使用命名插值，名称表达含义而不是位置。
- 复数、序数、性别和选择分支使用国际化库提供的消息能力。
- 不将标点、空格或括号拆成独立翻译片段。
- 包含链接、强调或交互元素的句子使用能够安全插入 React 元素的翻译方式，不拼接 HTML。

## 数字、日期和列表

- 日期、时间、数字、百分比、货币和列表使用基于当前 Locale 的格式化能力。
- 禁止用固定模板手工拼接年月日、千位分隔符和货币符号。
- API 时间进入展示层前必须具有明确的时区语义。
- 相对时间必须使用可本地化单位和复数规则。
- 排序、搜索和大小写转换需要语言语义时使用 Locale 感知能力。

## 组件与无障碍文案

- `placeholder` 不能替代可见或可访问标签。
- 图标按钮、关闭按钮、导航按钮和状态图标必须有翻译后的可访问名称。
- `title`、`aria-label`、`aria-description`、图片 `alt` 和屏幕阅读器专用文字必须国际化。
- 错误信息应描述用户可以采取的动作，不直接展示服务器内部文本。
- 翻译长度变化不能破坏布局；避免固定宽度或按字符数截断关键操作文案。

## 上游组件

- `components/ui` 和 `components/assistant-ui` 的源码边界不构成用户可见硬编码的豁免。
- 优先通过组件 Props、包装组件或统一消息映射注入翻译。
- 上游组件没有公开文案入口时，可以做最小本地修改，或在确认长期维护后转为自有组件。
- 禁止仅为翻译批量重写上游文件的无关结构和格式。
- 未在产品中实际渲染的上游示例文案可以保留；一旦进入用户界面必须完成本地化。

## HTML 语言与方向

- 应用初始化和语言切换时必须同步更新 `document.documentElement.lang`。
- 必须根据语言同步更新 `document.documentElement.dir`。
- 布局使用逻辑方向属性和能够适应 LTR/RTL 的组件结构。
- 不在组件中使用语言名称推断方向，方向由国际化配置统一提供。

## 检测与持久化

语言选择优先级必须固定：

1. 用户显式保存的有效偏好。
2. 浏览器或系统支持的语言。
3. 项目默认语言。

- 持久化键使用 `preferences.language`。
- 组件和 Hook 不得直接读写语言存储，必须通过 `i18n/preference.ts` 的适配边界。
- 读取存储必须捕获权限、解析和损坏数据异常。
- 从旧键迁移时兼容读取 `just-coast.language`；成功写入新键后移除旧键。
- 跨标签页更新必须验证新值属于支持语言。
- 服务端、存储和浏览器检测结果不能绕过支持语言列表。

## 加载与失败

- 默认语言关键资源应满足首屏可用性要求，避免界面显示原始 Key。
- 异步加载语言资源时必须处理加载失败并回退到可用语言。
- 缺失翻译在开发环境应可检测，在生产环境不得使整个界面崩溃。
- 不把原始 Key 或内部错误信息当作长期生产回退文案。

## 测试与评审

- 新增文案必须检查所有支持语言是否存在相同 Key。
- 关键页面至少验证默认语言、另一种支持语言和长文案布局。
- 语言切换必须验证内容、`lang`、`dir` 和持久化状态同步。
- 日期、数字、复数和插值必须覆盖具有差异的 Locale。
- Code Review 必须检查 JSX 文本、属性文案、错误分支和上游组件实际渲染内容。

## 项目案例

以下案例覆盖本文件全部规则章节。示例以项目当前 `zh-CN`、`en-US` 和 `src/i18n` 结构为基线。

### 案例：识别哪些内容需要翻译

**覆盖**：全部用户文案、禁止硬编码、开发文本例外、品牌/协议/用户内容、单一事实来源、同变更多语言。

```tsx
// ❌ UI 固定文案硬编码
<Button aria-label="Close">Sign in</Button>

// ✅ 文案和 ARIA 同时来自资源
const { t } = useTranslation("auth")
<Button aria-label={t("login.closeLabel")}>{t("login.submit")}</Button>
```

开发日志、测试名称和代码注释无需翻译。`just-coast` 品牌、用户昵称和后端数据保持原值，但“欢迎，{name}”的固定句式必须翻译。新增 Key 在 `zh-CN` 与 `en-US` 同一变更补齐，组件不维护第二套 fallback 文案。

### 案例：只通过项目 i18n 边界访问语言

**覆盖**：唯一入口、资源路径、locale 配置、初始化聚合、React/非 React 调用、`useLocale` 与 `ButtonLanguage`。

```tsx
// ✅ React 组件按 namespace 使用
const { t } = useTranslation("auth");
const { locale, setLocale } = useLocale();
```

- 资源位于 `src/i18n/resources/zh-CN/auth.json` 与 `en-US/auth.json`。
- namespace 注册留在 `i18n/config.ts`，支持语言留在 `locale.ts`。
- 偏好读写与旧键迁移留在 `i18n/preference.ts`，页面和组件不直接访问存储。
- 非 React 错误映射确有需要时才使用项目导出的 `i18n.t()`。
- 可复用语言按钮文件使用 `button-language.tsx`、导出 `ButtonLanguage`；页面不直接操作 i18next 或存储。

### 案例：规范 Locale 与区域回退

**覆盖**：BCP 47、集中支持/默认/回退、禁止组件检测、区域匹配、不支持值安全回退。

```ts
parseSupportedLocale("zh-CN"); // "zh-CN"
parseSupportedLocale("zh-Hans-CN"); // 按集中映射回退到 "zh-CN"
parseSupportedLocale("en-GB"); // 按项目策略匹配 "en-US" 或默认语言
parseSupportedLocale("unknown"); // DEFAULT_LOCALE
```

组件不能自行写 `navigator.language.startsWith("zh")`，也不能各自维护 `cn -> zh-CN` 别名。异常 Locale 不得中断初始化。

### 案例：资源 Key 表达语义

**覆盖**：namespace、小驼峰语义 Key、`common` 边界、上下文差异、删除/重命名同步、类型注册。

```json
{
  "login": {
    "submit": "登录",
    "submitting": "正在登录"
  }
}
```

- ❌ 使用 `"登录": "登录"` 或把所有字符串塞进 `common`。
- ✅ `auth.login.submit` 表达职责；“关闭账户”和“关闭弹窗”若翻译上下文不同，使用不同 Key。
- 删除或重命名功能时同步所有语言；新增 namespace 或语言时同步 `config.ts` 和 `i18next.d.ts` 类型来源。

### 案例：整句翻译与命名插值

**覆盖**：禁止拼句子、命名变量、复数/选择能力、标点不可拆、React 元素安全插入。

```tsx
// ❌ 假定语序并拆标点
const message = t("greeting") + userName + "!";

// ✅ 整句资源控制语序
t("welcomeUser", { userName });
```

消息数量使用 i18n 的复数能力，不写 `count + " messages"`。含帮助链接的句子使用安全的 React 翻译组件插入元素，不能拼接 HTML 字符串。

### 案例：Locale 感知格式化

**覆盖**：日期/时间/数字/百分比/货币/列表、禁止固定模板、时区、相对时间、排序搜索大小写。

```ts
new Intl.DateTimeFormat(locale, {
  dateStyle: "medium",
  timeZone: userTimeZone,
}).format(date);
new Intl.NumberFormat(locale, { style: "currency", currency: "CNY" }).format(
  amount,
);
new Intl.ListFormat(locale, { style: "long", type: "conjunction" }).format(
  names,
);
```

不要手写 `YYYY年MM月DD日`、千分位或货币符号。API 时间必须先明确是 UTC instant 还是本地时间。相对时间使用本地化单位；需要语言语义的排序使用 `Intl.Collator`。

### 案例：标签和可访问名称都要翻译

**覆盖**：placeholder 不替代标签、图标/导航/状态名称、ARIA/alt/title、可行动错误、长文案布局。

```tsx
<Label htmlFor="password">{t("login.passwordLabel")}</Label>
<Input
  id="password"
  placeholder={t("login.passwordPlaceholder")}
  aria-describedby="password-help"
/>
<p id="password-help">{t("login.passwordHelp")}</p>
```

图标按钮、图片 `alt`、`title`、错误和屏幕阅读器文字同样翻译。错误应说明下一步，如“请检查网络后重试”，不直接展示后端内部消息。长英文不能被固定宽度截掉关键按钮。

### 案例：为上游组件注入文案

**覆盖**：上游不豁免、Props/包装/映射、最小修改或转自有、禁止批量重写、未渲染示例例外。

- ✅ 通过 Tooltip Props 或自有包装向 assistant-ui 按钮传入翻译后的名称。
- ❌ 因一个按钮文案批量重排整个官方目录。
- 边界：没有公开入口时最小修改；深度长期维护则迁为自有组件。官方源码中未被产品渲染的示例文本可保留，一旦进入界面必须本地化。

### 案例：同步 HTML 语言和方向

**覆盖**：`lang`、`dir`、逻辑方向、禁止组件猜方向。

```ts
document.documentElement.lang = locale;
document.documentElement.dir = getLocaleDirection(locale);
```

布局优先使用 inline-start/inline-end 语义或支持 RTL 的组件能力。组件不能根据语言显示名称中是否包含“阿拉伯语”猜方向；方向来自集中 locale 配置。

### 案例：语言优先级和旧键迁移

**覆盖**：固定优先级、新键、异常处理、旧键迁移、跨标签校验、支持列表。

```text
1. preferences.language 中有效值
2. 浏览器/系统值匹配到支持语言
3. DEFAULT_LOCALE
```

读取存储捕获权限和损坏异常。迁移时先读新键，再兼容 `just-coast.language`；合法旧值成功写入新键后才删除旧键。`storage` 事件值不在支持列表时忽略并回退，不能直接接受服务端或浏览器任意字符串。

### 案例：资源加载失败仍可用

**覆盖**：首屏关键资源、异步失败回退、开发缺失检测、生产回退质量。

- ✅ 默认语言关键 namespace 随首屏可用，避免短暂显示 `auth.login.submit`。
- ✅ 切换语言资源加载失败时保留当前可用语言并显示国际化错误提示。
- ✅ 开发环境报告缺失 Key；生产界面不崩溃，也不长期把原始 Key 或内部错误当成用户文案。

### 案例：国际化测试矩阵

**覆盖**：Key 完整、双语言和长文案、内容/lang/dir/持久化、格式差异、Code Review 全路径。

| 测试       | 断言                                           |
| ---------- | ---------------------------------------------- |
| 资源一致性 | `zh-CN` 与 `en-US` 具有相同必需 Key            |
| 切换语言   | 可见内容、`html.lang`、`html.dir`、存储同步    |
| 长文案     | 表单、按钮、Dialog 在窄屏不溢出                |
| 格式化     | 日期、数字、复数和插值在两个 Locale 有正确差异 |
| 错误路径   | 属性文案、Toast、ARIA 与上游实际渲染内容均翻译 |

评审不能只搜索 JSX 文本节点；还要检查 placeholder、`alt`、ARIA、错误分支和通过上游 Props 注入的文案。

# 性能规范

## 原则

- 正确性和可维护性优先于未经测量的微优化。
- 性能优化必须针对明确瓶颈，并使用构建结果、浏览器分析或可复现实验验证。
- 优先解决请求瀑布、过大依赖、重复工作和不必要渲染等结构性问题。
- 不得为了理论性能增加明显复杂度而没有可说明收益。

## 请求与异步流程

- 互不依赖的请求应并行启动，不得无原因串行等待。
- 只有确认当前分支需要某个结果后才等待它，不能用提前 `await` 阻塞无需该结果的路径。
- 只依赖部分结果的工作应尽早开始，避免在组件树深处才发起关键请求。
- 用户输入触发的请求必须处理防抖、取消和过期响应。
- 重复访问的数据应根据实际时效建立明确缓存策略，不能永久缓存或每次无条件重取。
- 预加载只用于高概率下一步资源，禁止在首屏无差别预取大量内容。

## 包体积

- 新依赖必须评估浏览器包体积和是否可按需加载。
- 禁止仅使用少量功能却导入完整大型库。
- 使用支持 tree shaking 的明确入口，避免经过会聚合大量模块的 barrel 导入。
- 第三方包使用其公开导入入口，不得为了绕过 barrel 擅自依赖未公开的深层路径。
- 路由级、低频弹窗和重型功能应在确有收益时动态导入。
- 不把关键首屏内容拆得过细，避免产生大量小请求和加载闪烁。
- 依赖升级后应关注构建体积和重复依赖变化。

## 代码分割与预加载

- 大型编辑器、图表、代码高亮、数学和媒体处理能力只能在所属功能边界加载。
- 懒加载以路由或完整功能为粒度，避免大量细碎 chunk。
- 只有用户悬停、聚焦等行为明确表达下一步意图时，才预加载对应低频功能。
- 动态导入必须使用构建工具可静态分析的路径。

## React 渲染

- 状态保持在需要它的最低层级，避免顶层状态更新导致整棵组件树重渲染。
- Context 按变化频率和职责拆分，消费者只订阅需要的数据。
- 派生值在渲染中计算，不使用 Effect 制造额外渲染。
- 列表使用稳定 key，避免错误复用或整列表重建。
- 不在渲染中反复执行明显昂贵的解析、排序或大型数据转换。
- 对已确认昂贵的计算或引用稳定契约使用缓存；不机械添加 `memo`、`useMemo` 和 `useCallback`。
- 大型派生界面已经造成输入卡顿时，可以评估 transition 或 `useDeferredValue`，普通表单不默认使用。
- 长列表真实出现渲染压力后，先评估已有组件能力、`content-visibility` 或成熟虚拟列表方案。
- 传递给高频子组件的数据应保持最小，避免庞大对象导致无关更新。

## 事件和浏览器工作

- 高频滚动、调整尺寸和指针事件避免每次同步执行重计算。
- 监听器必须及时清理；可使用被动监听的滚动类事件应使用被动模式。
- 大量 DOM 测量和写入应分组，避免交替读取和写入导致布局抖动。
- 长任务应拆分或移出关键交互路径，但不能破坏状态一致性。
- 不在多个组件重复注册相同全局监听。

## 样式与动画

- 优先使用不会触发布局的动画属性。
- 避免大面积阴影、模糊和持续动画造成不必要绘制成本。
- 隐藏内容不应继续运行不必要的计时器和动画。
- 必须尊重 reduced-motion。
- 骨架屏和占位布局应尽量稳定尺寸，减少内容加载后的布局偏移。

## 图片、字体与资源

- 图片按实际展示尺寸提供，避免下载远大于显示区域的资源。
- 非首屏图片使用合理懒加载，首屏关键图片不得因错误懒加载延迟显示。
- 为图片和媒体提供尺寸或稳定容器，减少布局偏移。
- 字体字重和字符集保持必要范围，避免重复加载。
- 静态资源通过构建系统管理缓存和内容哈希，不手工制造易失效版本参数。

## 验证

- 性能修改前后使用相同场景比较。
- 记录主要指标、测试设备或浏览器、数据规模和网络条件。
- 同时检查性能优化是否影响错误处理、可访问性和用户体验。
- 生产构建结果是包体积判断依据，开发模式表现不能直接代表生产环境。
- 未得到改善或增加维护成本的优化应撤销。

## 项目案例

以下案例覆盖本文件全部规则章节。性能结论必须来自相同场景下的可重复数据，示例中的数值仅说明记录格式。

### 案例：先证明瓶颈再优化

**覆盖**：正确性优先、测量依据、结构性问题优先、复杂度必须有收益。

```text
场景：首次打开聊天页，Fast 4G，4x CPU slowdown，生产构建
变更前：首屏 JS 820 KiB，关键内容 2.8 s，可复现请求瀑布 3 层
目标：先并行独立请求并延迟重型 Markdown 扩展
```

- ❌ 没有分析就给所有组件添加 `memo` 和 `useCallback`。
- ✅ 先解决可观测的瀑布和重型依赖；若复杂缓存没有可说明收益，保持更简单且正确的实现。

### 案例：并行请求和按需等待

**覆盖**：独立请求并行、分支后 await、尽早启动、防抖取消、缓存时效、谨慎预加载。

```ts
// ❌ 无依赖却串行
const profile = await getProfile();
const permissions = await getPermissions();

// ✅ 同时启动
const [profile, permissions] = await Promise.all([
  getProfile(),
  getPermissions(),
]);
```

只有管理员分支才需要审计数据时，先判断权限再 `await import` 或请求。搜索输入防抖并取消旧请求。用户资料缓存必须定义多久有效及何时重新验证；不能永久缓存。只在用户聚焦设置入口等高概率信号出现时预加载对应功能。

### 案例：依赖和导入体积

**覆盖**：新依赖评估、按需功能、tree shaking、公开入口、动态重型功能、避免过细、升级回归。

- ❌ 为一个日期格式导入完整多语言工具包，或从聚合 barrel 导入整个图表集合。
- ✅ 优先使用现有 `date-fns` 的公开、可 tree-shake 入口；图表只在相关路由加载。
- ❌ 为了“最小 chunk”把每个按钮和图标都 lazy，导致加载闪烁和大量请求。
- ✅ 依赖升级前后比较生产构建体积、重复依赖和关键 chunk，不能只看版本成功安装。

### 案例：功能粒度代码分割

**覆盖**：编辑器/图表/高亮/数学/媒体边界、功能 chunk、意图预加载、静态路径。

```tsx
const AnalyticsPanel = lazy(
  () => import("@/analytics/components/AnalyticsPanel"),
);

function handleAnalyticsIntent() {
  void import("@/analytics/components/AnalyticsPanel");
}
```

用户悬停或聚焦分析入口时可预加载；不能首屏无差别加载编辑器、图表、KaTeX 和媒体处理。动态路径必须是 Vite 能静态分析的字面量，不能由任意字符串拼接。

### 案例：降低 React 重渲染成本

**覆盖**：状态层级、Context 拆分、派生值、稳定 key、昂贵计算、证据型缓存、transition、长列表、最小 Props。

- 把输入框草稿留在表单而不是顶层 App，避免每次按键重渲染整棵树。
- 将高频消息数据与稳定线程操作拆为不同订阅边界。
- 渲染中直接派生 `filteredMessages`，不使用 Effect 复制 State；已确认大型排序昂贵时才 `useMemo`。
- 列表用 `message.id`，不使用随机 key。
- 输入确实因大型派生界面卡顿时测量 `useDeferredValue`/transition；普通登录表单不默认加入。
- 长列表先测量，再评估已有滚动能力、`content-visibility` 或成熟虚拟化；子项只接收需要字段。

### 案例：高频浏览器事件

**覆盖**：避免同步重算、清理、被动监听、DOM 读写分组、长任务、全局监听集中。

```ts
window.addEventListener("scroll", handleScroll, { passive: true });
return () => window.removeEventListener("scroll", handleScroll);
```

不要让多个组件各自监听 resize 并在每个事件里交替读取 `getBoundingClientRect()`、写样式、再读取布局。由集中订阅批量读取和写入；长计算分片或移出关键交互路径，同时保持状态原子一致。

### 案例：动画和布局稳定

**覆盖**：transform/opacity、绘制成本、隐藏资源、reduced-motion、骨架尺寸。

- ❌ 持续动画 `width`、大面积 blur 和多个无限阴影；隐藏面板仍运行计时器。
- ✅ 动画 `transform`/`opacity`，隐藏后停止不必要任务，为 reduced-motion 提供无动画状态。
- ✅ 骨架与真实头像、标题和按钮使用相近稳定尺寸，减少加载后布局偏移。

### 案例：图片、字体和缓存资源

**覆盖**：实际尺寸、懒加载边界、媒体尺寸、必要字体、构建哈希。

- 64px 头像不下载 4000px 原图；使用匹配密度资源。
- 非首屏插图可懒加载，首屏关键品牌图不要错误 lazy 导致迟显。
- 图片提供宽高或稳定 aspect ratio。
- 只加载实际使用的字体字重和字符集。
- 资源通过 Vite 导入获得内容哈希，不手写 `logo.svg?v=17` 作为缓存方案。

### 案例：性能变更的通过标准

**覆盖**：同场景对比、完整记录、回归检查、生产构建、无收益撤销。

```text
设备/浏览器：同一台设备，Chrome 同版本
网络/数据：Fast 4G，1,000 条消息
构建：npm run build 的生产产物
前：输入响应 p95 180 ms；后：95 ms
回归：错误恢复、键盘焦点、reduced-motion、空状态均通过
```

开发模式快不代表生产包变小。若指标未改善或维护复杂度明显增加，应撤销优化而不是保留“也许以后有用”的代码。

# just-coast 前端开发规范

本目录是 `web` 前端项目唯一生效的开发规范。规则已经结合项目技术栈、现有代码、团队约定和可执行工具完成裁决；开发时不得再用其他风格指南覆盖本目录中的结论。

## 项目基线

- React 19 + Vite 8。
- TypeScript 6，启用严格类型检查。
- Tailwind CSS 4，使用 CSS-first 配置方式。
- shadcn/ui 与 assistant-ui 提供基础和生成组件。
- 所有用户可见内容支持国际化和主题切换。
- 前端工作目录为 `web`，项目内模块统一通过 `@/` 别名导入。

## 规则强度

- **必须**：不可省略。能够自动检查的规则必须由 ESLint、TypeScript、Prettier、Stylelint、Commitlint 或 CI 执行。
- **应该**：默认遵守。只有存在明确、可说明的项目原因时才可偏离。
- **可以**：根据场景选择，不得强制其他代码无理由统一。

规则中的“禁止”与“不得”等同于“必须不”。

## 冲突处理

出现冲突时按以下顺序裁决：

1. 当前任务的明确需求、安全要求和数据保护要求。
2. 本目录中适用范围最具体的编号规则。
3. `web/AGENTS.md` 中的项目边界。
4. 项目实际生效的 TypeScript、ESLint、Prettier、Stylelint 和 CI 配置。
5. 当前模块已经形成且不降低代码质量的局部约定。

同级规则发生冲突时，优先满足安全、正确性、可访问性和可维护性，格式与个人偏好不能覆盖这些目标。无法确定时应先停止扩散改动，记录冲突并完成统一裁决。

## 单一事实来源

- 格式细节由 Prettier 决定，规范文档不重复维护可自动格式化的细节。
- 类型正确性由 TypeScript 决定，禁止通过关闭严格检查绕过问题。
- 代码语义和项目边界由 ESLint 检查。
- CSS 语义和样式边界由 Stylelint 检查。
- 提交消息由 Commitlint 检查。
- 文档负责说明工具无法完整表达的设计原则、适用范围和例外。

规范与工具配置不一致时，不得长期并存。应在同一变更中修正规则或配置，使两者重新一致。

## 自有代码与上游代码

以下目录属于上游或生成代码边界：

- `web/src/components/ui`
- `web/src/components/assistant-ui`

这些目录允许保留上游命名、文件结构和必要实现方式。不得为了满足自有代码风格而批量重写；需要定制时优先在自有目录中包装或组合。直接修改时必须保持改动最小，并确认后续更新不会静默覆盖。

除上述目录外均视为自有代码，必须遵守完整项目规范。

## 修改规范

修改规范必须同时检查：

- 是否符合当前依赖和运行方式。
- 是否与其他编号规则重复或冲突。
- 是否能被现有工具执行。
- 是否会要求对上游生成代码做无意义修改。
- 是否需要迁移现有代码或持久化数据。
- 是否已给出足够明确的正确和错误边界。

新增规则必须解决真实、可复现或高风险的问题，不得仅因个人风格偏好增加维护成本。
